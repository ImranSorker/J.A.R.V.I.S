## REMAININGISSUES

- Full `pytest -q` still emits one `PytestUnraisableExceptionWarning`/unawaited `asyncio.to_thread` warning from the Python 3.13 + pytest-asyncio validation environment; the affected tests pass, and the strict smoke gate passes. This is not being falsely reported as a clean zero-warning pytest run.
- Flet-dependent UI tests cannot be executed until Flet is installed in the validation environment; GUI implementation uses `page.run_task()`, progress states and workspace revalidation but target-platform rendering remains unverified here.
- Optional runtime integrations are unavailable in this environment (`lancedb`, `sentence-transformers`, Whisper, TTS backend); JARVIS degrades gracefully, but target hardware/software validation is still required.
- Host-level `pip check` remains red because the shared validation environment contains `Pillow 12.3.0` while its unrelated preinstalled `moviepy 2.2.1` package requires `<12`; the JARVIS project itself declares `pillow>=10,<12` and does not control the preinstalled host package set.
- The current tree provides the distributed orchestration foundation but not a newly invented cross-machine transport; deployment-grade remote worker networking remains the principal V12.7 systems-engineering task.
- V0–V8 feature/module completeness cannot be certified because no V0–V8 source archives were found in the accessible Library set; claiming exact historical coverage for those releases would be unsupported.
